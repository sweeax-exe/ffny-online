| D15 | 2026-09-19 | Frames are verified by capturing the host's own back buffer (`RECOMP_TRANS_SHOT`), never by screenshotting the desktop, and golden baselines store measurements rather than pixels | A desktop capture catches whatever else is on screen, which already happened once (D12). A rendered frame is also EA artwork, so it cannot live in a public repository; `scripts/frame-signature.py` records the drawn region, pixel and colour counts and a hash, which is enough to catch a regression. |
| D16 | 2026-09-19 | GPU registers that cannot be plain memory get one trapped page each in `src/hooks/nv2a_regs.c`, rather than trapping the whole 0xFD000000 aperture | The aperture is 16 MB and the title drives the push-buffer pointers through it every frame; trapping all of it would put a page fault on the hot path. Two pages cover both registers found so far, and the blocks the title uses per frame stay plain memory. |
| D17 | 2026-09-19 | `in`/`out` are translated by the lifter into runtime calls, and unknown ports report no device rather than being stubbed per port | A dropped instruction leaves the destination register holding the previous instruction's value, which is silent and non-deterministic; a modelled port that returns zero is at least the same answer every time, and the access is counted so the log can name it. Zero is also the truthful answer on a machine with nothing pending and nothing busy, which is the rule the NV2A interrupt registers already follow. |
| D18 | 2026-09-21 | The emulated gamepad reports `bMaxPacketSize0 = 0x20`, not 8. | Eight is legal USB, but this title's driver is built for a Controller S, which reports 32. With 8 the driver consumed the first device descriptor and let its control endpoint go dormant; with 32 it runs the rest of the enumeration sequence (second port reset and all). Every other field in the descriptor already matched the real pad exactly, so the 8 was a transcription slip rather than a choice. |
| D19 | 2026-09-21 | Physical-to-virtual translation for hardware models is answered from the translations the kernel actually handed out, not by arithmetic. | `MmGetPhysicalAddress` subtracts the contiguous base inside that window and is the identity outside it, so a physical address is ambiguous: `0x3CC934` is both the physical form of contiguous `0x803CC934` and the identity form of ordinary `0x3CC934`. The OHCI model guessed "contiguous" and was wrong for exactly the buffer that mattered. Recording each translation as it is made costs a page-granular table of a few hundred entries and is right by construction; the old arithmetic stays as the fallback for addresses that never came through the kernel. |
| D20 | 2026-09-21 | The zero flag is lifted as a real variable, `_zf`, the way the carry already was. | A conditional jump that lands on a label cannot know which predecessor arrived, so the lifter fell back to `_flags` -- a variable it declares and never assigns, making the branch silently always false. `_cf` already solved this for the carry by being a real variable that survives the block boundary; `_zf` does the same for the zero flag, written by every `cmp`, `test`, `inc` and `dec`. This was not a tidy-up: an always-false branch in the Flash player's insert path destroyed every movie-load request the front end made, which is why the title never reached its menu. |
| D21 | 2026-09-23 | A switch whose jump table has been overwritten dispatches on its index instead. | The lifter reads the table at lift time to find the targets, so it already knows the index-to-target mapping and need not trust the table to survive in guest memory. The value comparison stays first, so a title that genuinely rewrites a jump table is still obeyed; only the case that would otherwise tail-jump to a non-address changes. Jump tables are the one part of an executable section the lifted code still reads at run time -- overwriting guest *code* is harmless in a static recompilation -- so this removes the only exposure that matters. |

| D22 | 2026-09-23 | `repe`/`repne` `cmps`/`scas` publish the full flag snapshot of the last pair compared (`_zf`, `_fa/_fb`, `_fcmp`, `_sf`, `_of`, `_cf` where the function needs it), leave the flags alone when `ecx` is 0, and `loop*` decrement `ecx` (patch 0009). Lifter regressions are counted by `scripts/lift-audit.py` rather than found by playing. | Found by a static scan of the generated C, not by a symptom: the carry was never written, so MSVC's inline memcmp (`repe cmpsb; je; sbb; sbb`) returned the same sign whatever the bytes. The same fix made Direct3D's `repe cmpsd` state compares return real answers (they compared `ebx == 0` and always said "identical"), so Present now waits for vblank: **~24 fps instead of ~100 fps is correct behaviour, not a regression.** |
| D23 | 2026-09-23 | `MmQueryStatistics` reports the emulated console's 64 MB minus a 2 MB kernel footprint, the XBE image and what the runtime's heap and contiguous allocators have handed out (patch 0011). | Titles size their own heaps from it. The old "half of 64 MB" gave this title an 18 MB main arena; the front end then got NULL for a 587 KB buffer, unpacked its loader movie over address 0, and never advanced. Now 56 MB available, 42 MB arena. |
| D24 | 2026-09-23 | The audio DSP doorbell is derived at run time as GP scratch page 0 + `0x810`, from `GPSADDR`'s scatter-gather table, instead of a hard-coded address (patch 0012). `RECOMP_APU_DSP_ACK` stays as an override. | The fixed address depended on heap layout and went stale with D23. Stale, it would have cleared a word inside the game's arena every audio frame. |
| D25 | 2026-09-23 | The GPU model stays "finishes everything on submit", made self-consistent: the fence mirror also sets `PGRAPH_PATT_COLOR0` to the submitted reference at the current `DMA_GET`. NOPs with a parameter raise PGRAPH's software-method interrupt (patch 0013). | Executing fences in order was tried and disagreed with the mirror, because D3D also completes work through software methods. A consistent instant model beats two half-models; the NOP interrupt is what D3D's push-buffer-space wait needs. |
| D26 | 2026-09-23 | No 'skip intro movies' patch; fix the movie by fixing audio. | Vlad chose to try the skip first and to fall back to the audio fix if it ran into trouble. It did: the title has no graceful path for a missing movie (20:00 entry). Skipping would mean forcing internal streamer state, which is patching game logic to hide a runtime gap. |
| D27 | 2026-09-23 | The APU model reads and writes physical addresses through the kernel's record of the translations it handed out, falling back to the contiguous window (`0x80000000 + P`), with a per-page cache (patch 0016). The interrupt line to DirectSound's service routine was written, found unexercised, and withdrawn. | Same rule as D19 for USB, for the same reason: DMA memory lives in the contiguous window, which here is separate storage from low RAM. The line was withdrawn because this title's DirectSound only uses looping buffers (EA mixes in software) and raised no notification in two minutes, so nothing tested it; the design is in `docs/04-improvement-backlog.md` for the first title that needs it. |
| D28 | 2026-09-23 | Every thread that runs guest code shares one host CPU (logical CPU 2; `RECOMP_GUEST_CORES=all` opts out). Host-side threads (GPU executor, APU, audio) stay free. | The console has one core, and titles rely on it without saying so. Def Jam's movie streamer publishes a queue's byte count, then its chunk pointer; the reader checks the count without the lock and follows the pointer. With guest threads on 24 cores the reader landed between the two stores and walked the ring from address 0 for ever, in 7 of 7 runs one evening. Pinned, 1 run in about 15. The title keeps its own preemption; only simultaneity goes. |
| D29 | 2026-09-23 | NV2A vertex programs run on the CPU in the push-buffer executor, with our own decoder following xemu's field layout, not the toolkit's `d3d8_vsh.c`. The viewport registers are mirrored into constants 58/59 as the hardware does (patch 0019). | The title sends stage coordinates and relies on the program, so drawing positions as pixels put every screen in the top-left. `d3d8_vsh.c` decodes a different bit layout and misreads this title's microcode (checked on `MAD oPos.xyz, R12, R1.x, c[59]`, D3D's epilogue). A CPU run needs no shader compiler, and Direct3D's epilogue leaves oPos in screen pixels already. |
| D30 | 2026-09-24 | GPU interrupts follow the hardware: each unit's status latches until the title acknowledges it (write-1-to-clear, on trapped PCRTC, PTIMER and PGRAPH pages), `PMC_INTR_0` is recomputed from status and enables, and one level-triggered delivery raises the interrupt while the summary and master enable are set (patch 0021). | The three deliveries that each cleared the others' bits ("PTIMER only", "PGRAPH only") worked only while sources never overlapped. When they did, Direct3D serviced one frame alarm twice and switched the alarm off. Refusing duplicate DPC inserts, the kernel-correct fix, broke those deliveries outright (6 of 8 stuck), which showed the model itself was the problem. |
| D31 | 2026-09-24 | stdout and stderr are fully buffered (64 KB), flushed by the explicit `fflush` calls, the crash handler and once a second by the timer thread. | Unbuffered, a redirected stream costs one `WriteFile` per character, and every logging thread, the GPU executor included, queues on the stderr lock behind it. Start-up crawled in about a quarter of runs; buffered, 10 of 10 runs play the intro. |
| D32 | 2026-09-24 | Seed every code-shaped start in the gaps between lifted functions (427, `scripts/gap-seeds.py`) in one re-lift, rather than one `[ICALL] Failed to resolve` per run. | Functions reached only through data (vtables, the USB class-driver table) are invisible to the lifter's call-graph walk, and each one found at run time cost a 20-minute re-lift. Guarded by comparing every function's `Original:` extent before and after: six moved, all corrections (a tail rejoined its function, SEH funclets stopped running into the next function); jump tables unchanged; both goldens match. The 115 smaller fragments a second pass finds were left unseeded. |
| D33 | 2026-09-24 | `RtlNtStatusToDosError` asks the host's `ntdll` instead of a seven-entry table. | The console's status codes are NT's, so the host's table is the complete and correct one. The short table turned `STATUS_NO_MORE_FILES`, the end of every directory listing, into 317, and the title's memory-card check read that as an error. |
| D34 | 2026-09-24 | The executor stops at every software method until the title acknowledges it, and runs push-buffer CALL/RETURN (patch 0027). Fences still complete on submit; holding them until the executor is level with PUT is opt-in (`RECOMP_FENCE_AT_PUT=1`). | Both are what the NV2A pusher does. With them, 9 of 9 runs reach the intro in 60 s; without the stall, 3 of 3 stopped at the legal screen. Holding the fences stopped the legal screen in 2 of 4, so the fence needs modelling reference by reference before it can follow the executor. |
| D35 | 2026-09-24 | Fences complete in push-buffer order: the executor runs D3D's semaphore release and pattern-colour methods, resumes after a software method only when PGRAPH FIFO access is back on, and a catch-up advances the fence to the newest reference before PUT when the executor is idle (patch 0028). | D3D reuses push-buffer space and fixup records on the fence's word; completing on submit let it overwrite commands the executor had not run, which is what crashed its DPC. The FIFO gate matches D3D's handler, which clears the interrupt before it patches. The catch-up exists because the walker still occasionally loses its place (D3D rewrites already-kicked commands in a way not yet understood); it turns that from a hang into a logged event. |

| D38 | 2026-09-25 | The translator honours the title's depth state (test, function, write mask, clear value, z in zeta-format units) rather than drawing every 2D batch with depth off, and draws colour-masked batches that write depth. `RECOMP_NO_DEPTH=1` opts out. | APT builds its masks out of depth (colour-masked passes that shape the depth buffer, then `LEQUAL` draws), so a front end drawn without depth loses every masked element: the menu titles and the memory-card popup. | D39 | 2026-09-26 | The emulated pad sits on game port 1: HC0's root hub reports four ports and the hub is on root port 3, because XAPI numbers root ports 3, 4, 1, 2 as game ports 1-4 (xemu wires them the same way). `RECOMP_PAD_PORT=1..4` moves it. | Def Jam binds players by port: on root port 1 the pad was player 3, and the P1-P4 join screen (M4b) never took it as P1. |
| D40 | 2026-09-26 | The GPU's interrupt preempts the title: a title thread entering the kernel waits while the executor is stopped at a software method or more than half a ring behind PUT (up to 50 ms; not at DISPATCH_LEVEL, not the interrupt thread). On by default, `RECOMP_GPU_PREEMPT=0` off. Vsync on the host present stays on (`RECOMP_PRESENT_VSYNC=0` off). | On the console the interrupt takes the one CPU and the GPU keeps pace, and Direct3D's ring reuse assumes both; without the wait it lapped the executor (the match load, the legal-screen stall). Without vsync the executor ran twice as fast but the intro movie stalled in 2 start-ups of 4. |
| D41 | 2026-09-28 | The host present no longer waits for vsync (patch 0071; `RECOMP_PRESENT_VSYNC=1` brings it back). Machine: Steam Deck, SteamOS 3.8 (no compiler, read-only system). Build environment: distrobox `djbuild`
(Arch, `cmake ninja clang pkgconf sdl3 shaderc vulkan-headers vulkan-icd-loader openssl python uv gdb
github-cli`); `gh` is logged in there and git pushes run from inside it. That container is rolling Arch:
since v0.6.2 (Dear ImGui's `atan2f`/`acosf`/`sqrtf`) its builds need GLIBC_2.43 and no longer start on
SteamOS (2.41). Build anything meant to run on SteamOS in the pinned image instead (the Linux setup's

`docs/build-macos-linux.md#steam-deck`). Data root

`uv run --no-project --with pyxbe --with capstone --with pytest python scripts/pipeline.py analyze|recomp|build`.
Run on SteamOS itself, not in the container (the container has no PipeWire library, so no sound there):
the binary needs at most GLIBC_2.38 and resolves against SteamOS's SDL3 3.2.18, Vulkan and shaderc
(`ldd -r` is clean). Analysis 1 min, lift 2 min, Clang build 2 min on the Deck.

Fixed (game): `_GNU_SOURCE` for `dladdr`; headless runs keep SIGINT/SIGTERM (SDL swallowed them with
no event loop). Fixed (toolkit): guest window reserved whole on Linux (arena in `win32_compat.c`); MMIO
decoder ALU forms; case-insensitive guest paths; POSIX clock overflow (`qemu_clock_get_ns/us`, PTIMER and
`NV_PAPU_XGSCNT` wrapped every 18 s) and the APU deadline running ahead during a pause; Vulkan texture
conversion out of write-combined staging memory (movies 10 -> 30 fps, soak 0/10 -> 10/10); vsync only on
displays at a multiple of 60 Hz, as on Windows (the Deck OLED's 90 Hz panel and a 144 Hz monitor held
the title to ~40 fps with FIFO; new `D3D8VkHost.refresh_hz`, filled by `src/host_posix.c`).

Results: quick 5/5 (`logs/regress-20261009-123014.txt`), soak 10/10, full 12 of 14 checks (`logs/regress-20261010-082035.txt` and reruns `regress-20261010-084419`, `-092011`, `-093159`): unit 210, the three goldens, fight, FFA, Terrordome FFA, replay (golden hash), intro, crib, gym and the boot soak pass; combat and versus pass every assertion but `audio.dry_queue` (2 and 7 isolated device underruns, no dropped buffers, the same through PipeWire on SteamOS).
