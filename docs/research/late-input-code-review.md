## Revised opportunistic acquisition review

The refresh path now emits `late_refresh_begin` before acquiring locks, tries the shared dispatch exclusion without raising IRQL, then tries the lifecycle mutex (`src/hooks/input_late.c:106-155`). This reverses the old lock-order concern: lifecycle-wrapped guest helpers may hold the lifecycle mutex and enter an XDK API that raises IRQL, but the refresh never waits for lifecycle while holding dispatch. If that mutex is busy, it releases dispatch immediately and leaves the ordinary report path in place. The XDK raise/lower inside `sub_0027E075` is recursive under either the legacy dispatch critical section or the dispatch gate; the new outer scope does not change guest IRQL. All successful acquisition paths release lifecycle before dispatch, and both acquisition-failure paths emit an end trace after releasing any lock they acquired.

The refresh still saves/restores the modeled integer, flags, direction, and x87 state around the injected guest calls (`input_late.c:84-103,132-155`). The converter/API wrapper itself has no modeled XMM operations. Dispatch-gate safe points save/restore the complete modeled guest register set, including XMM/MMX (`tools/xboxrecomp/src/kernel/kernel_hal.c:498-524,567-598`), so a posted interrupt serviced during nested raise/lower does not leave guest registers clobbered. Host start now advances the previous per-slot queue generation before clearing the queue (`tools/xboxrecomp/src/input/input_host.c:950-955`), preventing a retained guest pending record from matching a restarted queue's generation. The supplied kernel IRQL/dispatch and restart fixture results were not rerun as part of this read-only review.

No concrete lock-order, lock-lifetime, or register-restoration defect found in the revised scope.
