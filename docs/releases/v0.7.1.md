# v0.7.1 — Icons and Steam artwork

Every executable, app bundle, launcher and shortcut now carries the shield from the game's own
menus, and the Linux setup gives the game's Steam shortcut library artwork on the Steam Deck.
No gameplay or runtime code changes. This release follows the Linux release (v0.7.0): it builds
on the Linux setup and its Steam shortcut.

## Changes

- **Icons everywhere.** The shield, rendered from the in-game texture at eight times its size
  with its edge re-sharpened, on a dark plate with the glow of the title screen's skyline:
  - Windows: `DefJamSetup.exe`, `DefJamLauncher.exe` and the game, each with file properties
    (description, version, product), the Start-menu and desktop shortcuts, and the icons of the
    wizard, launcher and game windows.
  - macOS: `Def Jam Setup.app`, `Def Jam Recompiled.app` (and the Desktop alias and
    `~/Applications` copy of it), and the Dock icon while the game runs.
  - Linux: the application-menu and desktop entries, the setup wizard window, and the game's
    window and taskbar icon.
- **Steam artwork for the Linux setup.** With **Add to Steam** (or `--steam-shortcut`), setup
  reads the shortcut's id back from Steam and places a portrait capsule (the official cover with
  the wordmark redrawn crisply on it), a wide capsule, a hero and a logo in the shortcut's
  `grid` folder. The title carries a **FAN RECOMP** tag so the port reads as a fan project; the
  plain, tag-less set stays in `branding/` for future editing. It never replaces artwork you chose, uninstalling removes only what it placed,
  and `--steam-art` places it later for a shortcut you added by hand. Restart Steam or switch to
  Gaming Mode to see it.
- **`branding/`.** All of it, plus a GitHub social preview image (plain and FAN RECOMP), is in the repository with
  `scripts/make-branding.py`, which rebuilds the set from its masters. CI pins every file by
  checksum (D98); see `branding/README.md`.

## The artwork

The artwork is the game's own: the shield, the title wordmark and the title-screen scene are
rendered from its textures, and the portrait starts from the official cover (a scan without its
logo, from a community upload on SteamGridDB). It remains the property of its rights holders;
the MIT licence does not cover it. The owner approved committing exactly these files.

## Validation and limits

- **Windows:** the setup was built from this tree and its asset check passed (the payload
  carries `branding/`); a full silent install from an XISO compiled the game, and the game exe,
  the installed launcher and the setup exe each carry the shield and their file properties
  (read back through the shell's icon and version calls); a running game window has its class
  icon registered; a copy of the shortcut script, pointed at a temporary folder, made shortcuts
  whose icon is the launcher's. The install check ran on a setup built before the version number moved
  to 0.7.1 and before the FAN RECOMP files were added (neither touches the game); the final 0.7.1 setup was
  then built from the pushed tree and passed the game-free asset check with all of `branding/` in its payload.
- **Linux logic:** 22 unit tests pass on Ubuntu (WSL), including the binary shortcut-file
  reader, the artwork placement (appid naming, the player's own art kept, uninstall) and the
  desktop entry's icon.
- **Not checked:** macOS (the bundle icon keys and the `.icns` are written but no Mac has run
  them); a Steam Deck and Steam itself (the grid file names and the
  appid read from `shortcuts.vdf` follow Steam's documented layout but were not seen working);
  the icon in the Dock and on Wayland taskbars; Windows icon caches may show an old icon until
  they refresh.
- The sources are 640x480-era art. The renders are as sharp as that allows; the backdrop is
  graded, not invented, and the hero extends the skyline past the scene.
- The setup scripts and the Linux launcher have no icon of their own (a shell script cannot
  carry one); the setup tarball's `DefJamSetup.sh` shows a generic icon in a file manager.
