# v0.7.0 — Linux and the Steam Deck

This release makes x86-64 Linux, and the Steam Deck in particular, a native platform alongside
Windows and macOS, with a setup that builds and installs the game for you. It runs natively, not
through Proton: Vulkan on the Deck's GPU, PipeWire sound and the Deck's own controls as a pad. The
launcher and F1 overlay of v0.6.2 are there too. Windows and macOS behave as in v0.6.2. No precompiled
game, dump or generated guest code is distributed: setup compiles the game on your computer from your
own supported USA Xbox dump.

## Changes

- **Linux setup.** `DefJamSetup-0.7.0-linux-x64.tar.gz`: unpack it and open `DefJamSetup.sh` (on the
  Steam Deck, in Desktop Mode, double-click it and choose Execute). Same steps as the Windows and macOS
  wizards (your ISO, XISO or extracted dump, an install and a data folder, shortcuts), plus **Add to
  Steam** so the game starts from Gaming Mode. It brings its own Python and needs nothing else of yours.
  On a computer without a compiler, such as the Deck, it builds in a container pinned to SteamOS 3.8's
  library versions. The container is fetched once, about 1 GB, so the first install needs an internet
  connection, and it then builds offline. The game runs on the system's own SDL3, Vulkan and shaderc. A
  first install on the Deck takes about five minutes; an update about two. `--silent`, `--uninstall`
  and the exit codes are as on the other platforms ([guide](../setup-installer.md#linux-setup)).
- **Native Linux.** Fixes found by the first Linux runs, in the toolkit (fork branch `defjam/linux-v0.6.1`,
  `24724b5`): the guest's 4 GB address window is reserved whole; the MMIO decoder handles the ALU forms
  the USB interrupt handler uses; guest paths match files whatever their case, as on the console;
  the audio and timer clocks no longer wrap every 18 seconds, and the audio deadline no longer runs
  ahead after a pause; textures are converted in ordinary memory instead of write-combined staging memory
  (movies went from 10 to 30 frames a second, and boot soaks from 0 of 10 to 10 of 10). In the game:
  `dladdr` builds, and test runs without a window can be stopped with Ctrl+C.
- **Vsync only at multiples of 60 Hz**, as on Windows. The Deck OLED's 90 Hz panel and a 144 Hz monitor
  held the title to about 40 frames a second with vsync on; the game now paces itself there. The log's
  `[HOST] display refresh` line says what was found.
- **Building by hand on the Deck.** The guide builds in a podman image pinned to SteamOS's libraries:
  a current Arch Linux container links Dear ImGui's maths against glibc 2.43, which SteamOS 3.8 does not
  have ([guide](../build-macos-linux.md#steam-deck)).
- **CI** builds and checks the Linux setup on every change, and the release attaches it with its SHA-256
  and provenance, like the other two setups (D96).

## Try it

Windows and macOS: update through your setup as for any release. Linux and Steam Deck: download the
tarball from this release and follow [Linux setup](../setup-installer.md#linux-setup). The setups are
unsigned.

## Validation and limits

- Steam Deck OLED, SteamOS 3.8: install, update, repair and uninstall through the setup; the installed
  game played by Vlad ("looks good"). The regression run on the Deck: `--quick` 5 of 5, launcher and
  overlay checks 2 of 2, boot soak 3 of 3, and 12 of the 14 checks of the full run (combat and versus fail
  only on a few audio-queue underruns).
- Vlad's full regressions on Windows and macOS of this release's code found no regressions.
- **A little audio clipping or distortion on the Deck** ([#11](https://github.com/vyanhursky/DefJamFFNY-recomp/issues/11)).
- On displays that are not at a multiple of 60 Hz (75, 90, 100, 144 Hz) the picture can tear, since the
  game paces itself without vsync.
- HD textures are not offered by the Linux setup yet.
- Not tried: a desktop Linux distribution with its own compiler (`--toolchain host`), the wizard
  driven by hand from start to finish, the Steam shortcut started from
  Gaming Mode, Proton.
