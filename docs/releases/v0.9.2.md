# v0.9.2 — Unlock everything for testing

This release adds opt-in debug switches for playtesting and regression runs. None of them
is on by default, so normal play is unchanged.

## Changes

- **Unlock all fighters and venues.** The retail game still contains the developers' own
  unlock-everything routine, which no menu or cheat code reaches. A new setting calls it, so
  any profile, a new one included, has all 74 fighters and every venue, and 10,000 reward
  points. Turn it on with the launcher's or the overlay's General page, "Debug - Unlock all
  Fighters and Venues (Requires Restart)", with `[debug] unlock_all = true` in `settings.ini`,
  or with `RECOMP_UNLOCK_ALL=1` for one run (`0` turns it off).
- **Choose the match.** `RECOMP_START_FIGHTERS=a,b[,c,d]` and `RECOMP_START_VENUE=n` replace
  the fighters and the venue at the moment a match starts, so any fighter on any venue can be
  tried without stepping through the menus. `RECOMP_START_LOG=1` prints what the game was given.
- **Debug label in fights.** `RECOMP_DEV_DEBUG=1` shows the game's own debug label under each
  health bar.
- **Test runs unlock by default.** The harness, `regress.py` and the scenario suite turn the
  unlock on for the runs they start (`--env RECOMP_UNLOCK_ALL=0`, or `--no-unlock` for the
  scenario suite, turns it off). The `replay` and `repeat` checks run without it, because the
  unlock changes how the pinned fight plays. A new `unlockopt` check covers the launcher option.
- `DEFJAM_HARNESS_SNAPSHOT_SAVE=<dir>` keeps the save area as a harness run left it.
- The game's "DEBUG MENU" and "JUMP STARTING" code is dead in the retail image (nothing can
  reach it), so there is no switch for it.

The investigation, with addresses, is in
[unlocking everything](../research/unlock-everything.md); the settings are in the
[settings reference](../settings-reference.md) and the
[testing harness guide](../09-testing-harness.md).

## Validation

Tested on a Mac (Apple Silicon), against a copy of the owner's profiles, rebuilt from the
merged source: Unlock Fighters goes from 20 of 74 (15 points) to 74 of 74 with the option on;
the new `unlockopt` check passes (the launcher checkbox saves the setting, a game started from
that file alone runs the unlock, and one without it does not); `launcher`, `overlay`, `unit`
and `replay` pass, and `replay` matches the recorded golden on this build. All 25 CI checks on
the pull request passed. Windows and Steam Deck were not run by hand for this release; CI builds them.

## Known limits

- The unlock changes the profile in memory and asks the game to save it. Keep it off for a save
  you care about. In the flows tried (a One on One, Unlock Rewards, Story into the crib) no
  profile file changed, so there is no saved all-unlocked profile; the switch replaces one.
- Story progress, songs and items are not unlocked.
- With the unlock on, the pinned replay fight gives 95 state records where the golden has 80;
  the cause is not known.
- The `combat` check's audio gate (`audio.dry_queue`) fails on the Mac used for testing, with
  or without this change and on v0.9.1 as well.

## Updating

Run the setup for your platform and update the existing installation. The setup builds the
game locally from your own dump and preserves player data. The new `[debug]` section appears in
`settings.ini` the first time the game starts.
