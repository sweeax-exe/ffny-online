# v0.6.2 — the launcher and in-game overlay on macOS

This release brings the start-up launcher and the F1 settings overlay, which Windows has had since
v0.4.0, to macOS on Apple Silicon. It is the same screen on both: display, texture, controller,
pad-button and keyboard settings, saved as you change them. The Windows game is unchanged. No
precompiled game, dump or generated guest code is distributed: setup compiles the game on your Mac
from your own supported USA Xbox dump.

## Changes

- **The launcher.** A window appears every time the game starts, before the game's own window, with
  the settings and **Play** and **Quit** buttons. Settings that are read only at start-up (render scale,
  who plays, how many controllers, the pad backend) apply to that very launch. Tick *Skip the launcher
  at start* to go straight in; hold **Shift** while opening `Def Jam Recompiled.app` to see it again, or
  `open "Def Jam Recompiled.app" --args --launcher` (`--no-launcher` skips it for one start).
  Closing it with the red button or Cmd+Q quits without starting the game. It is drawn through Metal by
  SDL's renderer and is sharp on a Retina display.
- **The overlay.** **F1** (or the pad's guide button, or both stick clicks held for half a second) opens the
  settings over the picture while the game keeps running with every input held at rest; Esc, the pad's B
  or the same key closes it. The pointer shows while it is open, also in full screen. On a Mac keyboard
  F1 is often the brightness key, so use **fn+F1** or choose another key in the General page.
  It is drawn by the toolkit's Vulkan present step, after the picture has been scaled into the window,
  so it is never in a test capture.
- **Every page works with mouse, keyboard and pad.** Learning a key or a pad button for a binding, the live
  view of each pad, the rumble test, and *Show settings.ini in Finder* are all there.
- **Setup.** The macOS setup now carries the Dear ImGui source (pinned by hash) and builds it offline with
  the game. `Def Jam Recompiled.app` hands the two launcher options on to the game and nothing else.
- **Toolkit.** `d3d8_vk_set_overlay` in the Vulkan backend (`defjam/macos-launcher` on the fork): a render pass
  on the window's image after the blit, opened only on frames where the host asks for it. A host that sets
  no overlay is unchanged.

## Try it

Update through the macOS setup as for any release (the setup is **unsigned**: macOS blocks it the first
time; choose **Done**, then System Settings → Privacy & Security → **Open Anyway**). Start the game as usual.

## Validation and limits

- Checked on arm64 macOS 26 by scripted runs, not by a person at the keyboard (the Mac's screen was locked
  during development): the launcher's rendered frame read back and looked at, tabs and checkboxes
  clicked, a changed setting found in `settings.ini`, *Play* continuing into the game and *Quit* leaving,
  `--launcher` and `--no-launcher`; the overlay opened by F1 through the real SDL event path, a tab clicked,
  an overlay key learned and saved, and opened and closed by a virtual gamepad; the window's picture
  read back with the overlay on it. The regression results are in the release record
  (`PROGRESS.md`, work log 2026-10-09).
- **Not run:** a full session by hand with a real keyboard, trackpad and DualSense; Shift held at start through
  the app bundle; macOS before 26; Intel Macs; the setup packaged and installed from the dmg with this
  change (the packaging change is covered by the unit tests and the asset check only). The Linux build compiles
  from the same sources and has not been run.
- **Windows was not re-run for this release.** The Windows launcher and overlay are expected to behave as
  in v0.6.1: their code (`pc_ui.cpp`) is shared and was only given platform guards around the Windows-specific
  calls (the lock, the clock, the fonts, the window type), and the Windows-only files are untouched. Windows CI
  does not build the game. A Windows build and a click through the launcher follow separately.
- Changing the window width or height in the overlay resizes the window at once, as on Windows (a first test by hand found
  that the settings changed but the window did not; fixed before release).
- Text boxes take typed characters, not input-method composition. Smooth (trackpad) scrolling in the overlay
  is not tuned.
