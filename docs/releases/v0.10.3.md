# v0.10.3 — Brightness, vignette and a setup fix

A brightness slider and options to remove or weaken the vignette, both in the launcher and the
in-game overlay, and a fix for Windows setup stopping with "Access is denied". First published as
a beta (pre-release) on 2026-10-19 and released after the owner's Steam Deck play-test.

## Changes

- **Brightness slider** ([#44](https://github.com/vyanhursky/DefJamFFNY-recomp/issues/44)).
  Display → Picture in the launcher and the in-game overlay (F1), 50-200, default 100. It
  brightens or darkens the mid-tones on top of the game's own brightness curve; black and white
  stay as they are, and 100 is the picture as before. Applies as you move it.
  `[display] brightness` in `settings.ini`, or `RECOMP_BRIGHTNESS`.
- **Vignette off, or weaker** ([#47](https://github.com/vyanhursky/DefJamFFNY-recomp/issues/47)).
  The darkened screen edges the venues draw can be turned off (**Vignette**), or faded toward the
  undarkened picture (**Vignette strength**, 0-100%). Both apply at once. `[display] vignette` and
  `vignette_strength`, or `RECOMP_VIGNETTE` / `RECOMP_VIGNETTE_STRENGTH`.
  [How both work](../research/picture-options.md).
- **Windows setup no longer stops on "Access is denied … status.txt"**
  ([#40](https://github.com/vyanhursky/DefJamFFNY-recomp/issues/40)). The wizard's progress
  file could be locked while setup replaced it, and one refusal stopped the whole installation
  (`WinError 5`). Progress updates are now best effort: a refused one keeps the previous text
  and setup carries on. The wizard also reads the file in a way that no longer blocks the
  replace. The fix is in the setup itself, so it helps from this release's setup onward.
- **For developers.** `regress.py --only picture` drives the launcher's new controls end to end;
  `scenario_suite.py --settings` accepts `brightness`, `vignette` and `vignette_strength`.

## Validation

- macOS (Apple Silicon): full regression 18 of 18 on the feature branch (the golden frames and
  the pinned fight replay are unchanged, so the defaults leave the picture and the game as
  before). Five repeatable fights measured each picture setting: vignette off lifts the
  darkened edges with the centre unchanged; strength 50 lands on the predicted blend; brightness
  150 lifts the mid-tones. A read-back of the window confirms brightness on screen.
- Setup: the new status tests fail on the old code and pass now; on hosted Windows, two tests
  hold the file with real Windows handles while setup writes to it.
- Hosted CI builds and tests Windows (MSVC, including the game-side sources), macOS and Linux.
- Steam Deck: the owner installed the beta with the Linux setup and play-tested it; brightness and
  both vignette options work as intended.
- Windows was not play-tested. CI builds the game-side sources with MSVC; the renderer maps the same
  blend factors, and the setup fix ran its Windows tests on hosted Windows.

## Known limits

- The vignette options were measured in the default One on One venue; other venues and Story
  scenes were not toured one by one.
- The earlier limits remain (scene loads, the Deck at render scale 3, Windows shader compiles,
  the intermittent audio-queue gate); see [known issues](../known-issues.md).

## Updating

Run the setup for your platform and update the existing installation. Setup builds the game locally from your own dump and preserves
player data. Your choices go into `settings.ini` as before; the three new settings start at
the values that keep the picture unchanged.
