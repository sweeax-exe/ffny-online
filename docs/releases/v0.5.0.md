# v0.5.0 — native macOS on Apple Silicon; Linux runtime

This source release adds a native arm64 macOS build of the game, drawn through
Vulkan (MoltenVK), and brings the runtime, its fixtures and the Vulkan device to
Linux x86-64. Windows is unchanged in features and gains one audio fix.

## Changes

- **macOS (Apple Silicon).** The analysis, the lift and the build run on a Mac
  (`scripts/pipeline.py`), and the game plays in a window or full screen with
  gamepads, keyboard and mouse through SDL3. See
  [Build on macOS and Linux](../build-macos-linux.md).
- **Vulkan renderer** for hosts without Direct3D 11. It reuses the existing
  combiner and vertex-program generators and reproduces the three image goldens
  and the simulation replay golden recorded on Windows.
- **Device registers off Windows.** Trapped pages are served from a signal
  handler, with an arm64 load/store decoder and 4 KB device pages inside the
  16 KB pages of Apple Silicon.
- **One guest CPU without thread affinity.** macOS cannot pin threads, and the
  game relies on its console's single core: its stream reader otherwise spins
  for ever (a freeze at a movie or the main menu). Game threads take turns
  instead, and are preempted only while they are in the recompiled code.
- **Audio, all hosts.** The audio chip model played the rest of a mixing period
  as silence whenever a sound ended and the game had asked to be told, cutting
  32 to 224 samples out of whatever else was playing. It now waits for the game
  to answer. Measured on macOS: 232 such holes in a five-minute fight before, none
  after.
- **Linux x86-64.** The runtime libraries, the native fixtures and the Vulkan
  device build and pass in hosted CI. The game itself has not been built or
  run on Linux yet.

## Known limits

- The start-up launcher and the in-game overlay are Windows-only: they draw
  through Direct3D 11. On macOS the game starts at once and `settings.ini` is
  edited by hand ([settings reference](../settings-reference.md)).
- macOS has no persistent shader cache; the first use of an effect can hitch.
- A game thread that has just woken can wait a few milliseconds for its turn
  on macOS (1 to 3 as a rule, 23 seen once).
- One two-player run on macOS logged a single unresolved indirect call through
  a stale callback slot and played on; it did not recur. Under investigation.
- Steam Deck and a native Linux game build are not validated.

## Build this version

```bash
git clone --recursive --branch v0.5.0 https://github.com/vyanhursky/DefJamFFNY-recomp.git
cd DefJamFFNY-recomp
```

On Windows follow [Build and play](../build-and-play.md); on macOS follow
[Build on macOS and Linux](../build-macos-linux.md). Use your own supported USA
Xbox dump. When updating an existing checkout, update submodules and rerun
analysis, recompilation and the build.

This is a source release. No game data, generated guest code or executable is included.

## Validation

The owner play-tested both builds on October 8, 2026: Windows "plays great",
and the macOS build "is good too", with a DualSense.

Local macOS validation (arm64, macOS 26) on the released sources:

- Full regression: all 14 checks pass. Twelve in one run; the two-player check
  on its second run (see known limits); the saved-profile Story routes against
  a copy of the save laid out as those routes expect.
- Unchanged image goldens and replay: 80 records across 1,800 simulation steps,
  the same hash as on Windows.
- The trap and guest-CPU fixtures, and 161 parent unit tests.

Windows validation for this release is the owner's play-test and hosted CI. The
automated Windows game regression was last run for v0.4.1; it was not rerun on
these sources.

Hosted CI builds the runtime and fixtures on Windows, Ubuntu and macOS without
game code; it does not run the game.
